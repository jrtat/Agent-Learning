# OpenViking 基础介绍

## 序言

> date: 2026/10/16

OpenViking 是一个面向 AI Agent 的**上下文数据库（Context Database）** 或 **记忆文件系统**。

它不只是把聊天记录转成向量，而是尝试将记忆、资源和技能组织成可检索、可导航、可管理的层次化上下文空间。

现在关于Agent记忆，各家都有各家的讨论，OpenViking 是字节旗下火山引擎推出的开源方案，是“**文件系统即记忆**”的典型代表。

## 系统定位

传统的向量记忆系统通常采用如下流程：

```text
聊天记录
  ↓
切分文本
  ↓
生成向量
  ↓
相似度搜索
  ↓
拼接若干文本片段
```

这种方式虽然简单，但存在一些问题：

- 文本片段之间缺乏层次关系；
  
- 找到的内容可能只是语义相似，并不一定真正相关；
  
- 重要事实、临时事件、项目资料（这些内容的来源、性质不同）容易混在一起；
  
- 召回结果容易碎片化或过量；
  
- 记忆难以修改、删除、审计和迁移（可管理性差）。

OpenViking 的目标是解决更完整的上下文管理问题：

> 让 Agent 能够长期**保存**、**组织**、**检索**和**治理**上下文，而不是简单地保存聊天历史。

## 核心理念：文件系统范式

OpenViking 使用类似**文件系统**的**虚拟 URI** 组织内容，例如：

```text

viking://user/<user_id>/memories/entities/软件部署/openviking.md

```

该URI不一定对应宿主机上的普通文件，而是 OpenViking 内部的虚拟资源路径。

它具有文件系统的典型特征：

- 有**目录**和**文件**；
  
- 有明确的**父子关系**；
  
- 可以**浏览目录**；
  
- 可以**用路径表达检索范围**；
  
- 可以**读取具体文件**；
  
- 可以**在高层目录保存摘要**；
  
- 可以**从粗粒度信息逐步展开到细粒度内容**。

例如：

```text

viking://user/jrtat/
├── memories/
│   ├── entities/
│   │   └── 软件部署/
│   │       └── openviking.md
│   └── events/
│       └── 2026/
│           └── 10/
│               └── 16/
│                   └── 记忆抽取全链路验证成功.md
├── resources/
└── skills/

```

这样，系统既可以把“软件部署”作为整体理解，也可以继续深入读取具体的一条记忆。

## 分层上下文检索

OpenViking 的检索可以概括为：

```
用户查询
  ↓
“查询意图”分析
  ↓
定位相关“目录、实体或资源”
  ↓
“语义检索”和“关键词检索”
  ↓
“按层次逐步展开”
  ↓
“组装”有限长度的“上下文”
```

这与单纯的向量数据库不同：

- **向量**负责找到*语义上相近的内容*；
  
- **文件系统层次**帮助系统*理解内容属于哪个范围*；
  
- **摘要**帮助系统*先判断目录是否相关*；
  
- **读取操作**负责*在需要时展开完整内容*。

因此，OpenViking 更像是：

> 结构化目录 + 语义索引 + 上下文组装系统。

目录是树，但 OpenViking 不是纯树状存储：树负责“范围与层次”，向量负责“语义相近”。

更准确的说法是——树状骨架 + 语义索引。


## 和"提示词 / 向量库"的区别

OpenViking 不是只服务一个 Agent：同一份库，DSH、Claude Code、Codex、OpenViking 自带的 VikingBot 都能接。

OpenViking 不是提示词模板：内容由服务端抽取、去重、合并，会自己长大。

OpenViking 不是单纯的向量库：每个文件除了向量，还有**分层摘要**。

- 目录/文件旁边自动生成 `.abstract.md`（L0，一句话）、`.overview.md`（L1，概览），原文是 L2。
  
- 检索先命中 L0/L1 定位，再按需读 L2 原文。这就是它能"先给结论、再给原文"的原因，也是它比"整篇塞进上下文"省 token 的原因。

## 三个入口（按场景选）

| 入口 | 适合做什么 | 代价 |
| --- | --- | --- |
| **DSH 对话**（插件已接管） | 日常：让它记、让它查、让它带 URI 回答。零操作 | 看不到中间过程，需要去 Studio 核对 |
| **Studio**（浏览器） | 看：库长什么样、任务跑完没有、原文是什么、记忆被抽成什么 | 要手动开，鉴权要点一次 |
| **ov CLI**（需安装） | 批量：脚本化导入、定时同步、CI 里用 | `npm i -g @openviking/cli` 并配连接 |

三者读写的是**同一份库**。日常只用 DSH；想"看见"就用 Studio；要自动化才装 CLI。

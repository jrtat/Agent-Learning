### 第一层：数据接入层

数据来源包括：

- Agent 与用户的对话；
  
- 显式保存的记忆；
  
- 本地文件；
  
- Git 仓库；
  
- 网页和在线文档；
  
- Agent Skill；
  
- 其他外部资源。

在 DSH 中，系统会对对话进行分析，提取其中**具有长期价值的信息**，例如：

- 用户事实；
  
- 用户偏好；
  
- 项目决策；
  
- 部署配置；
  
- 失败经验；
  
- 重要事件；
  
- 可复用的操作经验。

### 第二层：语义处理层

OpenViking 通常需要两类模型能力。

#### Embedding 模型

Embedding 模型负责将文本转换为向量，用于相似度检索。

它主要解决：**哪些内容在语义上与当前查询相近**？

#### VLM / LLM模型

VLM 或 LLM 负责更复杂的语义处理，例如：

- **从对话中抽取长期记忆**；

- **生成目录和文件摘要**；
  
- **分析查询意图**；
  
- **组织上下文**；
  
- **对导入资源进行语义理解**。


### 第四层：索引与检索层

OpenViking 的检索不只有**向量搜索**，还可能结合：

- **语义搜索**；
  
- **关键词搜索**；
  
- **URI 和目录浏览**；
  
- **文件读取**；
  
- **目录摘要**；
  
- **按层次递归展开**；
  
- **记忆、资源和技能的分类检索**。

### 第五层：服务与客户端层

当前部署可以抽象为：

```text

DSH
 └── OpenViking Memory Plugin
      └── OpenViking Client/MCP
           └── OpenViking Server
                ├── 数据存储
                ├── 向量索引
                ├── Embedding 服务
                └── VLM/LLM 服务

```

当前服务端运行在 Docker 容器中：

```text

容器名：openviking

端口：1933

```

DSH 通过客户端配置和用户密钥访问 OpenViking。

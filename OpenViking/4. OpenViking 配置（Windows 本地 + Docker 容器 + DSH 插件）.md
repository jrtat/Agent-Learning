# OpenViking 配置

## 序言

> date：2026/11/8

由大肥鱼创作，我负责校对，写给第一次用 OpenViking 的人。

本篇回答的是：OpenViking 中，哪些地方是可以手动配置的，又分别有什么用？

## 可调项（默认值其实够用）

行为参数写在 profile 的 `cordis.patch.yml`（`%USERPROFILE%\.dsh\profiles\web\cordis.patch.yml`），追加一条**同 id** 的条目即可覆盖：

```yaml
- id: openviking-memory-runtime
  config:
    recallTokenBudget: 2000      # 每步召回注入的 token 预算
    scoreThreshold: 0.35         # 相关度阈值，调高=更严
    commitTokenThreshold: 20000  # 累计多少 token 提交一次会话
    captureToolResults: true     # 是否把工具结果也纳入会话记录
    skillCatalog: true           # 会话开头是否注入技能清单
    peerSource: git              # 记忆分区依据：git / cwd
```

以下是常用环境变量表，其优先级高于上述配置。

| 环境变量 |	它管哪一环	| 默认值	|
|---|---|---|
| `OPENVIKING_URL`（别名 `_BASE_URL`）|	插件往哪台服务发请求：召回、捕获、工具调用全走它 |	`http://127.0.0.1:1933`	|
| `OPENVIKING_API_KEY`（别名 `_BEARER_TOKEN`）	| 鉴权，以 `Authorization: Bearer` 发出	| 空 → 回落到 `ovcli.conf` 的 `api_key`	| 
| `OPENVIKING_RECALL_PEER_SCOPE`	| 召回时看不看别的 peer：`all` 跨 peer，`actor` 只看当前 peer | `all`	| 
| `OPENVIKING_PEER_ID`	| 把当前 actor peer 钉死成一个固定值	| 空 → 按工作目录自动推导	| 
| `OPENVIKING_DEBUG` + `OPENVIKING_DEBUG_LOG`	| MCP 代理那个共享进程的调试日志	| 关 / 空	| 
| `OPENVIKING_RECALL_TOKEN_BUDGET` | 每次注入多少召回内容 | `2000` | 
| `OPENVIKING_SCORE_THRESHOLD` |  相关度门槛多高 | `0.35` | 

改完重启 DSH web，用 `dsh --profile web --dump-config` 确认 `openviking-memory-runtime` 下出现了你的配置。

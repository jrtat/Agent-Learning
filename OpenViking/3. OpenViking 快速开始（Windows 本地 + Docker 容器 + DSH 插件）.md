# OpenViking 快速开始

## 序言

> 写给第一次用 OpenViking 的人。目标是**建立正确的心智模型，了解OpenViking全部主要功能**，并且知道哪些事是它在你背后自动干的。

> date：2026/10/16

### 什么是 OpenViking

一句话来说：**OpenViking 是给 Agent 用的"上下文数据库"，用文件系统的隐喻管理三类东西。**

| 类别 | 存什么 | URI 根 |
| --- | --- | --- |
| 记忆 memory | 你是谁、你的偏好、发生过什么事、定过什么决定 | `viking://user/<你>/memories/` |
| 资料 resource | 你导入的文档、网页、仓库（会被解析、切块、向量化） | `viking://resources/`、`viking://user/<你>/resources/` |
| 技能 skill | 一份 `SKILL.md` 形式的操作说明，任何接进来的 Agent 都能用 | `viking://~/skills/`、`viking://agent/skills/` |

`viking://` 是**虚拟路径，不是磁盘路径**。它长得像文件夹、能用 `ls`/`tree`/`grep`/`read` 操作，但背后是数据库 + 向量索引。

至于详细介绍，请转到隔壁。

### 和"提示词 / 向量库"的区别

OpenViking 不是提示词模板：内容由服务端抽取、去重、合并，会自己长大。

OpenViking 不是单纯的向量库：每个文件除了向量，还有**分层摘要**。
- 目录/文件旁边自动生成 `.abstract.md`（L0，一句话）、`.overview.md`（L1，概览），原文是 L2。
- 检索先命中 L0/L1 定位，再按需读 L2 原文。这就是它能"先给结论、再给原文"的原因，也是它比"整篇塞进上下文"省 token 的原因。

OpenViking 不是只服务一个 Agent：同一份库，DSH、Claude Code、Codex、OpenViking 自带的 VikingBot 都能接。

### 记忆有"分区"（peer）

一条记忆写在哪个空间，取决于**你当时在哪个工作目录**：

- 目录是 git 仓库 → 用仓库 `origin` 归一化成 peer（同一个仓库的 clone / worktree / 子目录共用一个）；

- 目录不是 git 仓库，也没配置 → **不发送 peer，记忆落到用户级空间** `viking://user/jrtat/memories`（全局共享）。

想让某个目录有独立记忆，在它下面放一个 `.openviking/config.json`：

```json
{ "version": 1, "peer": { "id": "一个独立的名字" } }
```
